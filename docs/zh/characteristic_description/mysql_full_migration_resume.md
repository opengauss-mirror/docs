# Mysql全量迁移断点续传

## 可获得性<a name="section56086982"></a>

本特性自openGauss 7.0.0版本开始引入。

## 特性简介<a name="section35020791"></a>

该特性实现了datakit迁移任务从Mysql迁移到opengauss端过程中发生失败，继续迁移时如何实现表级断点续传，即已经迁移成功的表不再重复迁移，从而提高迁移效率。

## 客户价值<a name="section46751668"></a>

通过使用断点续传功能，可提高迁移效率，降低迁移失败的风险。

## 特性描述<a name="section18111828"></a>

前端提供“继续迁移”按钮，在全量迁移或数据校验失败的场景下通过点击该按钮，后端可实现断点续传，该按钮只在迁移失败状态下可用，其他状态下不显示“继续迁移”按钮。

离线或在线迁移的的全量迁移失败后都可使用断点续传功能，增量迁移或反向迁移过程中失败，该功能不可用。

在数据校验过程中失败，点击“继续迁移”按钮，已迁移完成的表不会再迁移，视图、存储过程、触发器、函数等对象会重新迁移，但会迁移失败，因为目标端已存在。

## 特性增强<a name="section28788730"></a>

无

## 特性约束<a name="section06531946143616"></a>

- 只在源端为Mysql的场景中可用断点续传功能。

- 只在迁移失败情况下可用断点续传功能，手动结束迁移任务之后不可进行断点续传。

## 依赖关系<a name="section57771982"></a>
