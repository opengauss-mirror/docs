# oGRecorder 主备参数同步

## 特性描述<a name="section16406154310471"></a>

本特性支持基于主节点通过grcmd setcfg、api调用、修改配置文件三种方式下的参数修改同步，不建议通过备机设置同步参数。同步参数为gr_inst.ini文件管控的MAX_SESSION_NUMS、RECV_MSG_POOL_SIZE、IP_WHITE_LIST、LOG_COMPRESSED、DATA_FILE_PATH、LOG_LEVEL、GR_NODES_LIST。其中grcmd setcfg与api调用方式修改立即生效类参数会立刻加载到内存并同步，而修改重启生效类的参数仅同步配置文件，生效需重启集群。配置文件修改有两类情况，第一种手动使用grcmd reload触发同步，第二种则是通过以10min为周期的定时任务进入同步流程。

## 特性约束<a name="section06531946143616"></a>

- 以下参数列为保留参数：LOG_HOME、LOG_FILE_COUNT、INST_ID、LISTEN_ADDR、SSL相关参数，不进行同步。
- 本特性支持的参数同步必须依赖gr_inst.ini文件及worm存储。
- 加载配置文件时，遵守参数类型的加载规则，重启生效类型的参数必须重启节点才能生效。
- grcmd setcfg支持memory（仅内存）、pfile（仅文件）和both（内存+文件）三种设置模式，参数同步功能同样适配这三种模式：
  - 若通过memory模式设置参数，同步时备节点同样仅内存生效，文件不生效；
  - 若通过pfile模式设置参数，同步时备节点同样仅文件生效，内存不生效；
  - 若通过both模式设置参数，同步时备节点的参数值在文件与内存中都生效；
  - 所有参数同步均基于对应模式加载参数。例如：主节点通过grcmd setcfg分别设置日志级别为内存生效的255和文件生效的254，备节点会同步此配置，保持内存生效255、文件生效254的一致状态。
  - 通过grcmd setcfg pfile/memory设置同步参数，会导致内存与文件不一致，若触发定时同步，文件内的立即生效类参数会被加载到内存。因此，不推荐使用该方式修改参数。
- 同步流程中如果发生failover或switchover进行换主时，大部分情况都能同步最新参数，部分极端场景下需要用户在新主节点重新配置最新参数，比如在主机维护共享配置文件期间主机异常退出，会导致共享配置文件的内容无法被更新。
- 不建议手动修改配置文件中的同步类参数。若在主机手动修改，需执行 grcmd reload 命令手动触发同步，确保修改内容同步至备机。严禁在备机修改同步类参数，此类操作无法触发同步机制，会导致主备机重启后参数不一致。


## 基本原理<a name="section8406461564716"></a>

在worm共享存储中维护共享配置文件，由主机写入，备机不能修改。主机在写完共享配置文件后广播同步消息给备机，备机收到同步消息后读取共享配置文件的内容，更新本地配置文件并加载。集群发生主备切换后，新主先用共享配置文件中的内容更新本地配置文件，然后再作为主机发起后续同步流程。

## 使用指导<a name="section8445461564354"></a>

系统以10min的周期定时同步主机配置到备节点，用户也可通过以下操作触发同步：

- 使用cm_ctl start启动集群（该状态下会将文件内的参数同步，不会同步重启生效类参数的内存状态）。
- 在主机使用grcmd setcfg或api修改配置参数。
- 进行switchover、failover触发换主。此时，新主节点用共享存储的配置文件覆盖本机配置文件，然后备节点用共享存储的配置文件覆盖本机配置文件。
- 备机加入集群，备节点用共享存储的配置文件覆盖本机配置文件。
- 手动修改主机配置文件后，执行 grcmd reload 命令触发同步。
