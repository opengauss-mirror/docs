# Deploying GaussMaster<a name="ZH-CN_TOPIC_0000002258589386"></a>

<!-- md-trans-meta sourceCommit=unknown translatedAt=2026-09-07T01:51:01.000Z -->

## Configuration File<a id="configfile"></a>

You can initialize the configuration directory by running the following command:

```
python3 startup.py service setup -c confpath
```

After the command is executed, two configuration files are generated in the confpath directory:

- gaussmaster.conf:

    This file defines the vector database, DBMind, log, WEB-SERVICE, and other information required by the GaussMaster service.

- model\_config.yaml:

    This file defines the large language model (LLM) information required by the GaussMaster service.

The details of gaussmaster.conf are described as follows:

```
# VECTOR section configures the connection information of the vector database.
[VECTOR]
host =
port =
vector_dbname = # Database name of the local knowledge base.
user =
metadatabase = # Stores intermediate results generated by GaussMaster, such as Q&A records and diagnosis reports.
l2_distance_threshold = 0.8 # Used for fault-tree retrieval in intelligent O&M fault diagnosis mode. Adjust it based on the actual situation of the embedding model.
ssl = true # Using secure protocol by default, users must provide a certificate path.
ssl_certfile = (null) # The certificate file for ssl connections.
ssl_keyfile = (null) # Certificate private key file.
ssl_ca_file = (null)  # CA certificate to validate requests.

# DBMIND section configures the connection information of DBMind.
[DBMIND]
api_prefix = http(s)://***/v1/api/ # base URL ends with /v1/api/
ssl_certfile = (null) # The certificate file for ssl connections.
ssl_keyfile = (null) # Certificate private key file.
ssl_ca_file = (null)  # CA certificate to validate requests.

# WEB-SERVICE configures the address of the GaussMaster backend service. The front-end page performs front-end and back-end binding through this address.
[WEB-SERVICE]
host =   # Which host to bind for web service. '0.0.0.0' means to bind all.
port =   # Port to listen for web service.
ssl_certfile = (null) # The certificate file for ssl connections.
ssl_keyfile = (null) # Certificate private key file.
ssl_ca_file = (null)  # CA certificate to validate requests.

# LOG section configures log information.
[LOG]
maxbytes = 10485760 # Default is 10Mb. Maximum size of a single log file. If maxbytes is zero, the file grows indefinitely.
backupcount = 1 # Number of backups of log files.
level = DEBUG  # Options: DEBUG, INFO, WARNING, ERROR.
log_directory = logs  # Directory to log.

# TIMEZONE section configures the default time zone of the GaussMaster service.
[TIMEZONE]
tz = UTC+8 # only supports UTC, example: UTC-8, UTC+8, UTC-8:35

# SAFETY section configures whether sensitive-question checking is enabled.
[SAFETY]
safety_check = false  # Whether to check the question involving unsafe inquiry
```

The current GaussMaster version supports only online model invocation. The details of model\_config.yaml are described as follows:

```
# Default LLM. To use an LLM, set the enable option of the corresponding model in online_llm to True.
model_name: pangu_sigma_unify_plugin_38b

# API address of the embedding model.
embedding_model:
  enable: True
  model_name: bge-large-finetune
  api_type: bge-large
  api_url: http://*.*.*.*:*/get_embedding_result
# API address of the reranker model.
reranker_model:
  enable: True
  model_name: bge-reranker-finetune
  api_type: bge-reranker
  api_url: http://*.*.*.*:*/get_reranker_result

# API address of the LLM. To enable a model, set its enable option to True; otherwise set it to False.
online_llm:
  pangu_sigma_unify_plugin_38b:
    enable: True
    api_type: Pangu
    api_url: http://*.*.*.*:*/chat/completions
    recommended_config:
      temperature: 0.7
      top_p: 1.0
  pangu_cloud_sigma_unify_plugin_38b:
    enable: False
    api_type: PanguCloud
    api_url: http://*.*.*.*:*/chat/completions
    recommended_config:
      temperature: 0.7
      top_p: 1.0
  Baichuan2-13B-Chat:
    enable: False
    api_type: Baichuan
    api_url: http://*.*.*.*:*/get_qa_baichuan
    recommended_config:
      temperature: 0.7
      top_p: 1.0
  chatglm3-6b:
    enable: False
    api_type: Chatglm

    recommended_config:
      temperature: 0.7

    enable: False
    api_type: Llama3
    api_url: http://*.*.*.*:*/get_llm_result_llama3
    recommended_config:
      temperature: 0.7
      top_p: 1.0
```

## Starting and Stopping the Service<a name="ZH-CN_TOPIC_0000002258486284"></a>

1. Create a configuration file by running the following command:

    ```
    python3 startup.py service setup -c confpath
    ```

2. After the preceding command is executed, gaussmaster.conf and model\_config.yaml are generated in the configpath directory. Modify these two files with a text editor as described in [Configuration File](#configfile).
3. (Mandatory) Disable HISTORY recording.

    ```
    # Modify the /etc/profile file in the root directory.
    vim /etc/profile
    # Set the HISTSIZE value to 0.
    HISTSIZE=0
    # Save /etc/profile.
    :wq
    # Make /etc/profile take effect.
    source /etc/profile
    ```

4. After the preceding configuration files are manually modified, run the following command to initialize the configuration items.

    ```
    echo '{"VECTOR_password": "********","WEB-SERVICE_ssl_keyfile_password": "********", "DBMIND_ssl_keyfile_password": "********"}' | python3 startup.py service setup -c confpath --initialize --initialize_vector_db --initialize_meta_db
    ```

    The preceding initialization command performs the following three steps:

    1. Create two key components: Key component A is stored in dynamic\_config.db under the confpath directory, and key component B is stored in encryption\_part\_b.bin under the confpath directory.
    2. Initialize the O&M knowledge base and the Q&A knowledge base.
    3. Initialize the metadata database.

    >[!NOTE]Note
    >
    >1. In the gaussmaster.conf configuration file, the VECTOR section configures the database information required by the GaussMaster service. "VECTOR\_password" specifies the password of "VECTOR\_user" for this section, "VECTOR\_vector\_dbname" is the name of the knowledge base, and "VECTOR\_metadatabase" is the name of the metadata database.
    >2. "--initialize\_vector\_db" is used to initialize the O&M knowledge base and the Q&A knowledge base used for intelligent Q&A. If you do not need to initialize the O&M knowledge base and the Q&A knowledge base, you can omit this parameter.
    >3. "--initialize\_meta\_db" is used to initialize the metadata database of the GaussMaster service, which stores intermediate business data. If you do not need to initialize the metadata database, you can omit this parameter.
    >4. If neither the knowledge base nor the metadata database needs to be initialized, neither "--initialize\_vector\_db" nor "--initialize\_meta\_db" needs to be appended to the initialization command, as shown below:
>
    > ```
    > echo '{"VECTOR_password": "********","WEB-SERVICE_ssl_keyfile_password": "********","DBMIND_ssl_keyfile_password": "********"}' | python3 startup.py service setup -c confpath --initialize
    >    ```
>
    >5. Before running the initialization command, create the databases vector\_dbname and metadatabase defined in the VECTOR section of the gaussmaster.conf configuration file. Otherwise, an error is reported.
    >6. "WEB-SERVICE\_ssl\_keyfile\_password" is the password of the private key of the GaussMaster service.
    >7. "DBMIND\_ssl\_keyfile\_password" is the password of the private key used to connect to the DBMind service.
    >8. The passwords of "WEB-SERVICE\_ssl\_keyfile\_password" and "DBMIND\_ssl\_keyfile\_password" must contain at least 8 characters and include at least two of the following character types: an uppercase letter, a lowercase letter, a digit, and a special character (\[\~\`!@\#$%^&\*\(\)-\_+\\\\|\{\};:,<.\>/?\]). If the complexity requirement is not met, initialization fails.

5. Run the startup command.

    ```
    python3 startup.py service start -c confpath
    ```

    After the preceding command is executed, a gaussmaster.pid file is generated in the confpath directory to record the process ID of the GaussMaster service.

    >[!NOTE]Note
    >
    >1. During the initialization or startup phase of the GaussMaster service, if the embedding model service or the reranker model service is unavailable, an error prompt is displayed. However, the GaussMaster service still starts, and the APIs that do not involve these model services can be used normally.
    >2. During the startup phase of the GaussMaster service, if the DBMind service is unavailable, an error prompt is displayed. However, the GaussMaster service still starts. The intelligent Q&A function works normally, but the intelligent O&M function is affected.
    >3. During the startup phase of the GaussMaster service, if the large language model service is unavailable, an error prompt is displayed. However, the GaussMaster service still starts, and the APIs that require the LLM service are affected.

6. After the GaussMaster service is started, run the stop command to stop the service.

    ```
    python3 startup.py service stop -c confpath
    ```

After the GaussMaster service is started, its logs are recorded in "confpath/logs/gaussmaster.log", where you can view detailed log records.

>[!NOTE]Note
>
>1. Do not perform initialization after the GaussMaster service is started. Otherwise, an error prompt is displayed.
>2. After the GaussMaster service is started, do not delete the configuration file directory. Otherwise, the stop command becomes invalid, or even the service process becomes abnormal.
