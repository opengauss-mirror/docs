## 4.1 Sensitive Information Output Issue<a name="section749764217348"></a>

DBMind validates log content for sensitive information. If a log line contains fields such as \["PASSWORD", "PWD", "AUTH", "USERNAME", "USER", "CERTIFICATE", "SSL"\] (case-insensitive), the line is replaced with "Involves sensitive information, details are ignored."

## 4.2 Creating an SSL Certificate for HTTPS Using openssl<a name="section158682041185713"></a>

The DBMind service supports SSL by default. Therefore, configure an SSL certificate before starting it. Certificates can be generated by performing the following steps.

1. Create the configuration file openssl.cnf. The file content is as follows (you can configure it in more detail as required):

    ```
    [req] 
    distinguished_name = req_distinguished_name 
    [req_distinguished_name]
    ```

2. Run the following command in the directory where `openssl.cnf` is located:

    ```
    openssl req -new -newkey rsa:2048 -days 365 -nodes -x509 -keyout private.key -out certificate.crt -subj "/C=BE/ST=Antwerp/L=Brasschaat/O=Inuits/CN=localhost" -addext "subjectAltName = IP:192.0.2.1" -config openssl.cnf
    ```

    >[!NOTE]Note
    >
    >- The openssl version must be 1.1.1 or later.
    >- -newkey rsa:2048: Generates a new RSA private key with a key length of 2048 bits and uses it to generate a certificate request.
    >- -subj "/C=BE/ST=Antwerp/L=Brasschaat/O=Inuits/CN=localhost": Sets the subject DN (Distinguished Name) of the certificate, including the country (C), state or province (ST), city or region (L), organization (O), and common name (CN). In this example, CN is set to localhost, which is generally used in local development environments.
    >- -addext "subjectAltName=IP": Specifies the IP addresses for which the certificate can be used. Change the IP addresses as required.
    >- The certificate generated above is for reference only. In actual scenarios, use a valid certificate to run the program to avoid security issues.

3. After the preceding command is executed, you are prompted to enter the private key password. After you enter the password as required, the private key file private.key and the certificate file certificate.crt are generated. The content of private.key starts with "-----BEGIN ENCRYPTED PRIVATE KEY-----", indicating that the private key is encrypted. You can configure the generated file paths in the WEB-SERVICE section of the [service subcommand](service.md).

>[!NOTE]Note
>
>Other SSL libraries can also be used to generate certificates, but ensure that the curl tool and the library are compatible.
>For example, after generating a certificate based on OpenSSL, to call the API of the GaussMaster service by using the curl command, first ensure that curl supports OpenSSL. You can check this by running the curl -V command. Then append the certificate path, private key path, and private key password parameters to the curl command, as shown in the following example.
>
>```
>curl -X 'GET' 'https://host:port/v1/api/xxx' -H 'accept: application/json' -H "Content-Type: application/json" --cacert /path/xxx.crt --key /path/xxx.key --cert /path/xxx.crt --pass "***"
>```

## 4.3 curl API Chinese Character Issue<a name="section5514195624212"></a>

When calling APIs by using curl, convert Chinese characters to the URL-encoded format.
