## Versions

openGauss 7.0.0 (LTS) is an LTS version released by openGauss in September 2026, with a lifecycle of 3 years. This document applies only to the enterprise edition.

7.0.0 (LTS) is compatible with the features and functions of previous versions. Its main features are as follows:

- Standard SQL support

    Supports the standard SQL92/SQL99/SQL2003/SQL2011 specifications, the GBK, UTF-8, and GB18030 character sets, SQL standard functions and analytic functions, and stored procedures.

- Database storage management

    Supports tablespaces, allowing different tables to be placed in different storage locations. The enterprise edition supports multiple storage engines such as Ustore, Astore, and MOT.

- Primary/standby deployment

    Transactions support ACID properties, single-node fault recovery, data synchronization between the primary and standby, and primary/standby switchover. The enterprise edition also provides the CM tool, which supports database instance state query, primary/standby switchover, log management, VIP management, and cluster state query and push.

- Resource pooling

    Supports a resource pooling architecture based on shared storage and shared memory, achieving real-time consistency for reads on standby nodes.

- Application programming interfaces

    Supports standard JDBC 4.0 and ODBC 3.5 features, Python and Go connection drivers, and MySQL protocol compatibility.

- Management tools

    Provides installation and deployment tools, instance start and stop tools, backup and restoration tools, scale-out and scale-in tools, and upgrade tools. Supports DataKit, a tool for the full lifecycle of data, and full/incremental/reverse migration tools for MySQL, Oracle, and PostgreSQL (PG), as well as a data verification tool.

- Security management

    Supports SSL secure network connections, user privilege management, password management, security audit, fine-grained ANY privilege control, and the TLCP protocol, ensuring database security at the management, application, system, and network layers.

- AI-powered capabilities

    The enterprise edition supports automatic parameter tuning, slow SQL discovery, single-query index recommendation, virtual indexes, workload index recommendation, database metric collection, prediction, and anomaly monitoring. The in-database AI native engine supports more than 10 high-performance machine learning algorithms.

Based on the Kunpeng SuperPoD UBS Memory service and the ub_dist_comm_queue (ubs-atomic library capability) distributed communication queue, it establishes a shared-memory ring buffer between nodes to enable zero-copy message exchange. ## Version Compatibility

- The default value of the GUC parameter [`d_format_behavior_compat_options`](https://docs.opengauss.org/en/docs/7.0.0/extension_reference/extension_reference/server/shark_guc_parameters.html#d_format_behavior_compat_options) is changed from empty to 'enable_sbr_identifier, default_collation'. This change affects only D-compatible databases. After the change, identifiers (including data types) enclosed in '[]' are supported by default, while '[]' is not supported as array syntax. For character type fields, the collation inherits the table-level collation when the table-level collation is not empty, and is set to the default collation corresponding to the database encoding when the table-level collation is empty. In upgrade scenarios, when upgrading through OM, if the user database contains D-compatible databases and is upgraded from a version before the change to a version after the change, the original `d_format_behavior_compat_options` value is retained after the upgrade without modification. If the old version does not contain D-compatible databases, the default value for new databases created after the upgrade is the new default value. [#9034](https://atomgit.com/opengauss/openGauss-server/pull/9034) [#1245](https://atomgit.com/opengauss/openGauss-OM/pull/1245) [@shijuzheng1997](https://atomgit.com/shijuzheng1997)
- Lock wait related views and functions add a `waitstart` field, which marks the time when the lock wait starts. Affected views and functions include [`dbe_perf.locks`](../sql_reference/dbe_perf_schema_locks.md), [`pg_catalog.pg_locks`](../database_reference/pg_locks.md), and [`pg_catalog.pg_lock_status`](../sql_reference/statistics_information_functions.md). [#9133](https://atomgit.com/opengauss/openGauss-server/pull/9133) [@2504_92042799](https://atomgit.com/2504_92042799)
- Sequence related views and functions support displaying global sequence information, indicating whether the current sequence is a global sequence. Affected views and functions include [`dbe_perf.statio_all_sequences`](../sql_reference/statio_all_sequences.md), [`information_schema.sequences`](../sql_reference/columns.md), [`pg_catalog.pg_gtt_attached_pids`](../database_reference/pg_gtt_attached_pids.md), [`pg_catalog.pg_seclabels`](../database_reference/pg_seclabels.md), [`pg_catalog.pg_statio_all_sequences`](../database_reference/pg_statio_all_sequences.md), [`pg_catalog.pg_sequence_all_parameters`](../sql_reference/system_information_functions.md), and [`pg_catalog.pg_sequence_parameters`](../sql_reference/system_information_functions.md). [#8647](https://atomgit.com/opengauss/openGauss-server/pull/8647) [@sunquancheng01](https://atomgit.com/sunquancheng01)
- The [`information_schema.columns`](../sql_reference/columns.md) view supports displaying identity-related information. The `is_identity`, `identity_generation`, `identity_start`, `identity_increment`, `identity_maximum`, `identity_minimum`, and `identity_cycle` columns display real information based on the identity status. Previously, the values of these columns were always NO or NULL. [#9137](https://atomgit.com/opengauss/openGauss-server/pull/9137) [@CXXXXZ](https://atomgit.com/CXXXXZ)
- [WLM statistics related views](../database_reference/pg_session_wlmstat.md) support displaying the number of RowDescription cache hits. Four fields are added: `rowdesc_a_store_count`, `rowdesc_a_hit_count`, `rowdesc_b_store_count`, and `rowdesc_b_hit_count`. They indicate the cumulative number of slots created and the cumulative number of cache hits for the RowDescription cache when connecting to openGauss through the openGauss protocol, and the corresponding cumulative slot creation count and cumulative cache hit count when connecting to openGauss through the MySQL protocol. RowDescription is used when processing D messages in the openGauss protocol and result set output in the MySQL protocol. [#2419](https://atomgit.com/opengauss/Plugin/pull/2419) [#9202](https://atomgit.com/opengauss/openGauss-server/pull/9202) [@wofanzheng](https://atomgit.com/wofanzheng)
- The `provolatile` attribute of the [`text_date`](../sql_reference/type_conversion_functions.md) function is changed from 'i' (immutable) to 's' (stable). This means that for a fixed input, the result of the function remains unchanged within a single scan, but the same input may produce different results across multiple scans. [#9548](https://atomgit.com/opengauss/openGauss-server/pull/9548) [@liyangx](https://atomgit.com/liyangx)

## Known Issues

- openGauss does not monitor file permissions or slow disks. When file permissions are abnormal, the database exits and the corresponding information is recorded in the log. On a slow disk, database operations become slower.
- MOT (Memory Optimized Tables) is incompatible with the incremental checkpoint feature. If MOT is used, the incremental checkpoint function must be disabled.
- LLVM does not work well with the ARM architecture, and LLVM-related errors are reported when TPCC data is imported into MOT. This can be avoided by not enabling JIT, which is controlled by the `enable_mot_codegen` switch. To reduce the performance impact of disabling JIT on TPCC tests, set `force_mot_pseudo_codegen = true`.

## Inherited Features

- **Basic Features**: [SQL standard syntax](../sql_reference/opengauss_sql.md), [data types](../sql_reference/numeric_types.md) (including [JSON and JSONB](../sql_reference/json_jsonb_types.md)), tables (including temporary tables, global temporary tables, and foreign tables), [views](../sql_reference/brief_tutorial/view.md), [materialized views](../sql_reference/materialized_view.md), foreign keys, [indexes](../sql_reference/indexes.md) (including btree, Gin, and hash indexes), [sequences](../database_administration_guide/creating_and_managing_sequences.md), functions, [triggers](../sql_reference/triggers.md), [aggregate functions](../sql_reference/aggregate_functions.md) such as `median`, ROWNUM, UPSERT, and the GB18030 character set.

- **SQL Engine Enhancements**: [Range, LIST, and HASH partitioning](../sql_reference/partitioned_tables.md#classification-of-range-partitioned-tables), automatic partition extension based on range partitioning, global partitioned indexes, row-store execution to vectorized execution, [autonomous transactions](../characteristic_description/autonomous_transaction.md), [parallel query](../characteristic_description/smp_for_parallel_execution.md), [Global Syscache](../characteristic_description/global_syscache.md), Global PlanCache, the [IPv6 protocol](../sql_reference/network_address_types.md), the [postgis plug-in](https://docs.opengauss.org/en/docs/7.0.0/extension_reference/PostGIS.html), and [event triggers](../characteristic_description/event_trigger.md). Supports [inherited tables](../sql_reference/create_table_inherits.md). Supports PIPELINED functions, which can return a set of rows. SELECT statements support data sampling on specified subpartitions, views, and materialized views through the [TABLESAMPLE clause](../sql_reference/select.md#parameter-description). A single trigger can be disabled or enabled through ALTER TRIGGER. SELECT statements support row-column conversion through the ROTATE and NOT ROTATE clauses. Table constraints can be enabled or disabled through SQL. Numbers ending with f or d are treated as floating-point numbers. 'NaN' and 'infinity' are supported to represent special floating-point values. The IS [NOT] INFINITE and IS [NOT] NAN conditional expressions are supported. For the numeric data type, precision can be greater than scale, and scale can be negative. The CROSS/OUTER APPLY JOIN syntax is supported. When an object referenced by a view (such as a table, column, function, or view) is modified or dropped, the view is set to an invalid state. Supports [XMLTABLE](../sql_reference/xmltable.md), which expands an XML document into relational table results by the specified row path, maps nodes, attributes, or expressions to output columns through the `COLUMNS` clause, and is used as a table function in the `FROM` clause. JSONB capabilities are enhanced: the [jsonb_path_exists](../sql_reference/json_jsonb_functions_and_operators.md) function checks whether any item exists at the specified JSON path, and the [jsonb_path_query_first](../sql_reference/json_jsonb_types.md#jsonpath-types) function extracts a specific expression from JSON data through JSONPATH.

- **Storage Engine Enhancements**: Delayed standby, [logical replication on standby](../characteristic_description/logical_replication.md), [parallel logical decoding](../characteristic_description/parallel_logical_decoding.md), [gray upgrade](../characteristic_description/gray_upgrade.md), [specified-node upgrade](../characteristic_description/rolling_upgrade.md), Hash indexes, primary key and unique constraints on column-store tables, the [Ustore storage engine](../database_administration_guide/in_place_update_storage_engine.md), [segment-page storage](../database_administration_guide/storage_structure.md#segment-page-storage-structure), [publication/subscription](../characteristic_description/publication_subscription.md), row-store table compression, [MOT memory tables](../database_administration_guide/mot_memory_and_storage_planning.md), and [NUMA-aware optimization](../database_administration_guide/numa_awareness_allocation_and_affinity.md). [Segment-page tables support space reclamation](../characteristic_description/segment_space_shrink.md). After DELETE and UPDATE operations on a segment-page table, space is reclaimed through system functions, so that the storage resources occupied by table files are released more effectively without affecting normal user services.

- **Resource Pooling**: The [openGauss three-tier pooling architecture](https://docs.opengauss.org/en/docs/7.0.0/resource_pooling/resource_pooling_overview.html) based on storage pooling, memory pooling, and compute pooling. [Optimized standby visibility judgment logic, optimized primary oldestxmin advancement logic, and standby snapshot caching](https://docs.opengauss.org/en/docs/7.0.0/performance_tuning_guide/resource_pooling_performance_optimization.html) achieve 60K tps on 2 nodes in sysbench scenarios, with 1.6x linearity, a 50% improvement over the pre-optimization baseline. Supports [transparent forwarding of write statements within a standby transaction to the primary for execution](https://docs.opengauss.org/en/docs/7.0.0/performance_tuning_guide/transparent_forwarding_within_backup_machine_affairs.html). [DSS capability enhancements](https://docs.opengauss.org/en/docs/7.0.0/resource_pooling/feature_enhancement.html) support the NoF/NoF+ protocol, thread pool mode for high-concurrency processing, upgrade mode, and black box diagnostics. With distributed storage, [database operator offloading](../characteristic_description/resource_pooling_operator_offloading.md) accelerates TPCH performance by 40%. Supports the [SPQ multi-node parallel query framework](https://docs.opengauss.org/en/docs/7.0.0/extension_reference/spqplugin.html). [DMS](https://docs.opengauss.org/en/docs/7.0.0/resource_pooling/dms_resource_statistics_function.html) and CBB add wait event statistics. Supports RTO < 10s under a 500K TPMC workload. Supports [primary/standby dual-cluster DR based on Dorado storage synchronous replication](https://docs.opengauss.org/en/docs/7.0.0/resource_pooling/resource_pooling_active_standby_dual_cluster_dr.html). Supports [resource pooling primary/standby dual-cluster DR based on stream replication](https://docs.opengauss.org/en/docs/7.0.0/resource_pooling/resource_pooling_active_standby_dual_cluster_dr.html). DDL execution is supported during the on-demand replay redo phase. Supports [offline scale-out and scale-in of resource pooling standbys](../tool_and_commandreference/gs_expansion.md). Supports [virtual machine deployment](../database_administration_guide/resource_pooling_om_installation_and_deployment.md#virtual-environment). Supports xlog log unification. Real-time build supports flow control. Supports [primary/standby parameter synchronization](https://docs.opengauss.org/en/docs/7.0.0/resource_pooling/resource_pooling_support_for_primary_and_backup_parameter_synchronization.html). Supports page storage. Supports scaling a dual cluster in to a single cluster. Supports [archiving](https://docs.opengauss.org/en/docs/7.0.0/resource_pooling/resource_pooling_xlog_support_archive.html).

- **Stored Procedures**: [Stored procedures](../sql_reference/stored_procedures.md), [commit/rollback within stored procedures](../sql_reference/transaction_management.md), and [stored procedure debugging](../characteristic_description/stored_procedure_debugging.md). Supports [stored procedure coverage tests](../sql_reference/proc_coverage_generate_stored_procedure_coverage_report.md). [Cursors](../sql_reference/cursors.md) support nested definition.
