# grcmd Tool Usage Guide

`grcmd` is the command-line management tool for the openGauss Data Vault (oGRecorder) component. It is used to manage and maintain the GR service, supporting functions such as configuration management, certificate generation, and service status queries.

## Basic Usage

```sh
grcmd [command] [OPTIONS]
```

- View help information:
  - Brief help: `grcmd -h` or `grcmd --help`
  - Detailed help: `grcmd -a` or `grcmd --all`
  - Version information: `grcmd -v` or `grcmd --version`

## Common Commands

| Command      | Description                                          |
| ------------ | ---------------------------------------------------- |
| ts           | Display current API call time consumption statistics  |
| lscli        | Display current client information                    |
| setcfg       | Set configuration parameters                          |
| getcfg       | Query configuration parameters                        |
| getstatus    | Query GR service status                              |
| stop         | Stop the GR service                                  |
| switchover   | Perform a primary-standby switchover                  |
| reload_certs | Reload certificates                                  |
| gencert      | Generate client/server certificates                   |
| reload       | Manually trigger parameter synchronization (primary only) |
| datausage    | Query data space usage                                |

## Command Details

### 1. ts

Display current API call time consumption statistics.

```sh
grcmd ts
```

### 2. lscli

Display current client process information.

```sh
grcmd lscli
```

### 3. setcfg

Set configuration parameters.

```sh
grcmd setcfg -n <name> -v <value> [-s <scope>]
```

- `-n/--name`: Configuration item name (required)
- `-v/--value`: Configuration item value (required)
- `-s/--scope`: Scope of effect. Optional values: `memory`, `pfile`, `both`. Default: `both`.

### 4. getcfg

Query configuration parameters.

```sh
grcmd getcfg -n <name>
```

- `-n/--name`: Configuration item name (required)

### 5. getstatus

Query GR service status.

```sh
grcmd getstatus
```

### 6. stop

Stop the GR service.

```sh
grcmd stop
```

### 7. switchover

Perform a primary-standby switchover.

```sh
grcmd switchover
```

### 8. reload_certs

Reload certificates.

```sh
grcmd reload_certs
```

### 9. gencert

Generate client or server certificates.

```sh
grcmd gencert -t <ca|client|server> [-d <days>]
```

- `-t/--type`: Certificate type, `ca`, `client`, or `server` (required)
- `-d/--days`: Certificate validity period in days (optional, default 3650)

> The environment variable `GR_HOME` must be set in advance. Certificates will be generated in the `$GR_HOME/CA` directory.
> It is recommended to set the certificate validity period longer than the worm protection time, to prevent the certificate from being modified after exceeding the worm protection time.
> When manually generating certificates via the grcmd command, you must first modify the certificate-related configurations such as `SER_SSL_KEY` and `CLI_SSL_KEY` in the configuration file, specifying an empty directory.
> Certificates generated by this command will automatically have their private keys encrypted.

### 10. reload

Trigger parameter synchronization (only allowed on the primary node). It is recommended to execute this after manually modifying the primary configuration file.

```sh
grcmd reload
```

### 11. datausage

Query data space usage.

```sh
grcmd datausage
```

## Notes

- Certain commands (such as setcfg, stop, switchover, gencert, datausage) will record operational logs.
- Before running, ensure that the environment variable `GR_HOME` is correctly set.

## Getting Help

- View all commands and parameter descriptions:

  ```sh
  grcmd --all
  ```

- View detailed help for a specific command:

  ```sh
  grcmd <command> -h
  ```
