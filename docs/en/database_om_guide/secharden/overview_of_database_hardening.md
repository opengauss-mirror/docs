# Overview of Database Hardening

<!-- md-trans-meta sourceCommit=unknown translatedAt=2026-07-21Txx:xx:xx.xxxZ -->

This section describes the objectives and methodology for hardening the openGauss system.

## Hardening Purpose

The primary objective of openGauss security hardening is to enhance database security by ensuring data confidentiality, integrity, and availability. Implementing a series of hardening measures reduces potential risks such as unauthorized access, data leakage, and malicious attacks. This protects user data and ensures continuous service operation.

## Hardening Solution

This section outlines the openGauss security hardening solution, covering methods and specific items.

### Hardening Methods

Administrators can manually modify openGauss configuration files (such as `postgresql.conf` and `pg_hba.conf`) to adjust security settings, including password policies, access control, and encrypted communications.

Additionally, adjusting database roles and permissions ensures that only authorized users can access and operate the database.

### Hardening Items

openGauss hardening items fall into the following ten categories:

- Connection Configuration
- File and Directory Security
- Security Authentication Configuration
- Account and Password Management
- Permission Management
- Database Audit
- Error Reporting and Log Configuration
- WAL Archiving Configuration
- Running Environment Configuration
- Other Configurations
