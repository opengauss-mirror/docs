# Logical Backup and Restoration<a name="EN-US_TOPIC_0289897021"></a>

-   **[gs\_dump](../ToolandCommandReference/gs_dump.md)**

    Plain-text output (the default, or `-F p`/`--format=plain`) contains matching `\restrict key` and `\unrestrict key` protection commands. `--restrict-key=RESTRICT_KEY` applies only to plain-text output and requires a nonempty ASCII alphanumeric key (`A-Z`, `a-z`, `0-9`); a random key is generated by default. Using this option with `-F c/d/t` causes an error. The `restore.sql` script embedded in a tar archive also includes restricted-mode protection. Before executing it with gsql, replace every `$$PATH$$` placeholder in `restore.sql` with the absolute path to the directory containing the extracted data files. For INSERT-mode dumps, retain the referenced `restore-<id>.sql` files in that directory, and preserve the generated `\restrict` and `\unrestrict` commands in all scripts; do not copy or execute `restore.sql` on its own.

-   **[gs\_dumpall](../ToolandCommandReference/gs_dumpall.md)**

    The plain-text output includes restricted-mode protection. `--restrict-key=RESTRICT_KEY` specifies a nonempty ASCII alphanumeric key and passes the explicitly specified value to each child gs\_dump process. If omitted, gs\_dumpall and each child gs\_dump generate their own random keys.

-   **[gs\_restore](../ToolandCommandReference/gs_restore.md)**

    The current CLI requires exactly one of `-d/--dbname` and `-l/--list`. It reports an error if neither is specified and does not provide restore script generation. Direct restoration with `-d` executes SQL through the database connection and does not send gsql meta-commands. `-l` lists the archive table of contents (TOC) to standard output, or to a specified file with `-f/--file`. The new `--restrict-key=RESTRICT_KEY` option is a compatibility/reserved parameter for script protection; it does not enable a script mode, cannot be used with `-d`, and is not used by `-l`. The script protection mechanism requires a nonempty ASCII alphanumeric key (`A-Z`, `a-z`, `0-9`), but the current CLI has no available mode that uses this key to generate a script.

A fixed key is intended for stable regression tests or output comparisons and is not recommended for routine production backups. It is neither a database password nor a backup encryption password. If the source database side can predict the key, protection against client-side command injection is weakened. Restore these scripts with a gsql client that supports `\restrict` and `\unrestrict`; do not remove the protection commands to accommodate an older client. [gsql restricted mode](../ToolandCommandReference/meta-command-reference.md#gsql-restricted-mode) limits client meta-commands and is not a SQL security sandbox. Restore only backups from trusted sources.
