# 1. config.json

CI 配置文件

```json
{
  "name": "xxx 文档检查配置",
  "config": {
    ...
  },
  "repo": {
    ...
  }
}
```

- name: 配置文件名称
- config: 模板配置，在此定义的配置可以在*仓库配置*中继承使用
- repo: 仓库配置，存放仓库的配置信息

## 1.1 字段说明

### 1.1.1 config

config 是一个对象，存放模板的配置信息，key 为模板名称，value 为模板的配置信息

- docPath: **必需字段**，文档路径，正则表达式，匹配到的文件将进行文档检查
- markdownlintConfig: 非必需字段，markdownlint 配置文件，可以是本地文件路径，也可以是网络文件路径
- urlWhitelist: 非必需字段，url 白名单文件，可以是本地文件路径，也可以是网络文件路径
- codespellWhitelist: 非必需字段，单词白名单文件，可以是本地文件路径，也可以是网络文件路径
- disableCheckExternalUrl: 非必需字段，是否禁用外链检查
- disableCheckInternalUrl: 非必需字段，是否禁用内链检查
- disableCheckAnchor: 非必需字段，是否禁用锚点检查
- disableCheckOnly404Status: 非必需字段，是否禁用只检查 404 状态的链接，禁用意味着将检查额外异常状态的链接，会增加误报
- disableMdInTocCheck: 非必需字段，是否禁用 toc-check 中的 markdown 文件是否加入 toc 检查
- ci: **必需字段**，启用的 CI 检测，支持如下 CI：
    - markdownlint: Markdown 语法检查
    - tag-closed-check: Html 标签闭合检查
    - link-validity-check: 链接有效性检查（包含：1. 内链；2. 外链；3.锚点）
    - resource-existence-check: 资源有效性检查（包含：1. 内链；2. 外链）
    - toc-check: Toc 检查（1. `_toc.yaml`语法是否正确_；2. 每一篇 md 文档都需要在目录中进行维护）
    - codespell-check: 单词拼写检查
    - file-naming-check: 目录和文件是否符合命名规范检查（小写字母，下划线连接）
    - file-naming-consistency-check: Markdown 中英文文档名称是否一致检查

```json
{
  "name": "xxx 文档检查配置",
  "config": {
    "base": {
      "docPath": ".*",
      "markdownlintConfig": "https://raw.gitcode.com/openeuler/docs/raw/stable-common/.doctools/markdownlint.config.json",
      "urlWhitelist": "https://raw.gitcode.com/openeuler/docs/raw/stable-common/.doctools/url.whitelist.txt",
      "codespellWhitelist": "https://raw.gitcode.com/openeuler/docs/raw/stable-common/.doctools/codespell.whitelist.txt",
      "disableCheckExternalUrl": false,
      "disableCheckInternalUrl": false,
      "disableCheckAnchor": false,
      "disableCheckOnly404Status": false,
      "ci": [
        "markdownlint",
        "tag-closed-check",
        "link-validity-check",
        "resource-existence-check",
        "toc-check",
        "codespell-check",
        "file-naming-check",
        "file-naming-consistency-check"
      ]
    }
  },
  "repo": {
    ...
  }
}
```

### 1.1.2 repo

repo 是一个对象，存放仓库的配置信息，key 为仓库名称（owner/name的形式，如果匹配所有仓库请填写 all），value 为仓库的配置信息

> 如：对于 <https://gitcode.com/openeuler/docs> 仓库，其 key 为 openeuler/docs

- extendConfig: 非必需字段，继承的模板名称，取值为 config 中定义的模板名称
- 其它字段：参考 [1.1.1 config](#111-config)，在仓库配置中定义后将覆盖模板中的字段
- branches: 非必需字段，仓库的分支配置，对分支使用自定义配置进行检查；key 为分支名称，value 为分支的配置信息
   - branches字段说明：
       - extendConfig: 非必需字段，继承的模板名称，取值为 config 中定义的模板名称，如果缺失该字段，则使用仓库配置
       - 覆盖字段：参考 [1.1.1 config](#111-config) 说明，在仓库配置中定义后将覆盖模板中的字段

```json
{
  "name": "xxx 文档检查配置",
  "config": {
    "base": {
      "docPath": ".*",
      "disableCheckExternalUrl": false,
      "disableCheckInternalUrl": false,
      "disableCheckAnchor": false,
      "disableCheckOnly404Status": false,
      ...
    }
  },
  "repo": {
    "openeuler/docs": {
      "extendConfig": "base",
      "disableCheckExternalUrl": true,
      "branches": {
        "master": {
          "disableCheckOnly404Status": true,
          "ci": [
            "markdownlint",
            "tag-closed-check",
            "link-validity-check",
            "resource-existence-check",
            "toc-check",
            "codespell-check",
            "file-naming-consistency-check"
          ]
        },
        "stable-25.03": {
          "ci": [
            "markdownlint",
            "tag-closed-check",
            "link-validity-check",
            "resource-existence-check",
            "toc-check",
            "codespell-check"
          ]
        }
      }
    }
  }
}
```

# 2. markdownlint.config.json

markdownlint 配置文件是一个 JSON 对象，相关的规则请查阅：<https://github.com/DavidAnson/markdownlint/blob/HEAD/doc/md001.md>

默认情况下开启所有规则（即 default 设置为 true），若要关闭某个规则，将规则值设置为 false 即可

    "style": "ordered"

# 3. url.whitelist.txt

url.whitelist.txt 是一个文本文件，存放白名单的链接，每一行是一个链接，支持正则匹配

# 4. codespell.whitelist.txt

codespell.whitelist.txt 是一个文本文件，存放白名单的单词，每一行是一个单词
